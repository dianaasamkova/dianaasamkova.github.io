Prodeology

Drag and drop over a virtualised tree

Result Rows stay still, illegal moves are impossible, and a move is usually one update instead of rewriting all siblings.
Problem
Most rows aren't in the DOM, rows jumped mid-drag, and some moves broke level rules.
Solution
Never mutate the tree during a drag; a custom drag row and drop line; level rules inside the drop check; fractional ordering.

Burny Games

Refresh storms and a memory leak

Result No refresh storms or sign-out loops since, and memory stays bounded.
Problem
Concurrent requests each tried to refresh the session, causing sign-out loops.
Solution
Made refresh single-flight at every layer that fans out, then found an unbounded cache in my own code and bounded it with LRU and a TTL.
  • NextAuth, OAuth2, JWT
  • Next.js App Router
  • Google OAuth
Burny Games

An endpoint that silently deleted data

Result No further link loss, one place for the rules, and cross-group linking later came with no new storage.
Problem
Links lived in two drifting stores, and a bulk endpoint treated anything missing from a request as a delete.
Solution
Unified the model into one store and redesigned the API around explicit deltas.
  • NestJS
  • Prisma + PostgreSQL
  • REST API design
Burny Games

Config that drifted on incremental sync

Result Fixed before the SDK-config service moved onto the new sync path, its first consumer.
Problem
Operators edit layered config (organization, project, environment); games read a resolved, permission-filtered copy kept current by delta sync. Deltas could disagree with a full fetch.
Solution
Found and fixed four delta-only bugs: a deleted override now falls back to the inherited value, deltas resolve references like a full fetch, and changes are scoped per environment and deduplicated by id.
  • NestJS
  • Redis
  • CDN config delivery
Burny Games

Automation rules that can't loop

Result Illegal chains can't be saved, and every rule run is all-or-nothing.
Problem
Users chain "when X happens, do Y" rules, so one rule can trigger another forever.
Solution
A cycle check over the rule graph when a rule is saved, under a lock; at runtime, budgets, lock ordering and one transaction.
  • Prisma + PostgreSQL
  • NestJS
  • Forms and validation

How I ship

Spec first

Design specs with acceptance criteria and a security review before any code.

Agree the contract early

API contracts are settled with backend when the work is split up, not discovered at code review.

AI writes, people decide

Agents implement and verify; I approve the spec and review the pull request.

The system behind it

  • Rules and skills

    Team conventions written down for the agents: UI patterns, styling, API architecture, and permissions inferred from the backend code. Verifiers check against the same rules.

  • Artifacts, not chat

    Every run leaves files: the spec, a traceability map, verification reports, amendments. Work survives a lost context, and every decision can be reviewed.

  • A wiki the agents maintain

    Cross-repo features start as specs in an Obsidian-style wiki that an LLM keeps current; I own the console's part. My own career notes follow the same pattern.
